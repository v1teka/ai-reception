# AI-ресепшн 24/7 — демо

В репозитории два демо:
- **веб-чат** для салона красоты и фитнес-клуба (этот раздел);
- **Telegram-бот для барбершопа** с записью на свободные слоты и панелью мастера — [см. ниже](#telegram-бот-для-барбершопа).


Чат-бот администратор для салона красоты или фитнес-клуба. Пишет как живой человек: коротко, тепло, со смайликами, может поболтать и всегда возвращает к записи.

Умеет:
- отвечать про услуги, цены, мастеров/тренеров, адрес, часы работы, акции;
- подбирать услугу или абонемент;
- записывать (собирает услугу, время, имя, телефон и подтверждает запись), переносить и отменять;
- поддерживать small talk.

Два демо-бизнеса в одной ссылке:
- `/` или `/?b=salon` — студия красоты «Лаванда»
- `/?b=fitness` — фитнес-клуб «PulseFit»

> Это демо: запись не уходит в реальную CRM, свободные слоты бот придумывает правдоподобно.

## Запуск локально

Нужен Node.js 20+ и ключ Anthropic API ([console.anthropic.com](https://console.anthropic.com)).

```bash
cp .env.example .env   # вписать ключ
npm start              # http://localhost:3000
```

Веб-чату зависимости не нужны (`npm install` нужен только Telegram-боту, см. ниже).

## Деплой в один клик (ссылка для клиентов)

1. Зайти на [vercel.com](https://vercel.com) → **Add New → Project** → выбрать этот репозиторий.
2. В **Environment Variables** добавить `ANTHROPIC_API_KEY`.
3. **Deploy**. Получите ссылку вида `https://ai-reception-xxx.vercel.app` — её можно отправлять клиентам.

## Как адаптировать под конкретного клиента

Всё в одном файле — `lib/businesses.js`: название, имя администратора, приветствие, кнопки-подсказки, адрес, услуги и цены. Поменяйте текст и задеплойте заново.

Модель по умолчанию — `claude-sonnet-5-5`, можно сменить переменной `ANTHROPIC_MODEL` (например, `claude-haiku-5-5` — быстрее и дешевле).

## Структура

```
public/index.html   — страница чата (мессенджер-стиль, без фреймворков)
api/chat.js         — бэкенд: POST /api/chat (Vercel-функция)
api/config.js       — шапка и приветствие для выбранного бизнеса
lib/businesses.js   — данные бизнесов (правьте здесь)
lib/chat.js         — промпт и запрос к Claude
server.js           — локальный сервер
```

# Telegram-бот для барбершопа

Живой ИИ-администратор в Telegram без кнопок-шаблонов: клиент пишет как обычно, бот отвечает по-человечески и записывает.

Что умеет:
- отвечает про услуги, цены, адрес, часы работы, мастеров и прочие «знания» точки;
- показывает свободные окна и записывает на выбранную услугу. Каждая услуга занимает 1–4 слота подряд (стрижка — 2 слота по 30 мин, «стрижка + борода» — 3, комплекс — 4);
- показывает и отменяет записи клиента, за 2 часа до визита присылает напоминание (даже если переписку в это время ведёт мастер);
- присылает мастеру в Telegram уведомление о каждой новой записи и отмене;
- пишет коротко, как живой администратор в мессенджере: по одному-два предложения, без дежурных фраз;
- перед ответом «печатает» — время пропорционально длине ответа, от 2 до 12 секунд: мгновенный ответ выдаёт бота. Если клиент дописал, пока бот печатал, устаревший ответ не уходит: бот переписывает его с учётом нового — дополняет, если новое о другом, или отвечает заново, если клиент уточнил вопрос;
- если не знает ответа или клиент прислал голосовое/фото — **пишет клиенту по-человечески, что уточнит и скоро ответит, и зовёт мастера**: присылает карточку с перепиской и черновиком ответа, а само фото, голосовое или файл — следом. Пока вопрос ждёт мастера, бот продолжает отвечать клиенту на всё остальное; если и на новое нужен мастер — пишет «Это тоже уточню и скоро отвечу» и дописывает вопрос в ту же карточку. Замолкает бот, только когда мастер взял диалог сам. Если ИИ не ответил вовремя или случился сбой — молчит и тоже зовёт мастера. Если готовый ответ не удалось отправить клиенту (сбой Telegram) — он остаётся черновиком в карточке мастера, и отправить его можно одним нажатием. «Бот, попробуй ещё» его тоже не теряет: бот досылает его сам, а если клиент за это время дописал — решает с учётом нового;
- понимает реакции клиента: 👍 на «Записать вас на 12:00?» — это ответ, а ❤️ на «Ждём вас!» — просто эмоция, на неё бот не отвечает. Реакции мастер видит сразу (если ведёт диалог сам) и в истории переписки. В чатах Telegram Business реакции клиентов Telegram ботам не присылает;
- точка — это данные, а не код: её можно импортировать с Яндекс.Карт, поправить словами или фото прайса и передать другому мастеру;
- **несколько заведений в одном боте**: у каждого своя ссылка для клиентов, свои данные, переписки и администраторы; заведение можно перевести в отдельного бота (см. [«Несколько заведений»](#несколько-заведений)).

> Пока точка не настроена, бот работает на демо-данных барбершопа «Бритва» с правдоподобно занятыми слотами. Записи хранятся в самом боте (`data/state.json`), во внешнюю CRM не уходят.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) и скопируйте токен.
2. Заполните `.env`:
   ```bash
   cp .env.example .env   # ANTHROPIC_API_KEY и TELEGRAM_BOT_TOKEN
   npm install
   npm run bot
   ```
3. В логе появится ссылка «стать владельцем» (`https://t.me/<бот>?start=own_…`). Откройте её — вы владелец, бот покажет панель мастера. Вместо ссылки можно сразу вписать свой Telegram ID в `OWNER_IDS`.

Бот работает через long polling — нужен постоянно запущенный процесс (VPS, Railway, Render, Fly.io, Docker), Vercel для него не подходит. Сервер должен быть в стране, где доступен Anthropic API. Данные лежат в `data/state.json` — эту папку нужно сохранять между перезапусками.

```bash
docker build -t barber-bot .
docker run -d --restart=always --log-opt max-size=10m --log-opt max-file=3 \
  --env-file .env -v $(pwd)/data:/app/data barber-bot
```

Хватит самого маленького VPS: процесс занимает около 80 МБ памяти и почти не нагружает процессор — вся тяжёлая работа идёт на стороне Anthropic API. `--log-opt` ограничивает логи Docker, чтобы они не съели диск. Перезапуск безопасен: по `docker stop` бот за несколько секунд дописывает начатые ответы, а сообщения за последний час, на которые не успел ответить, подхватывает после старта.

### Автодеплой на свой сервер

Push в `main` → GitHub Actions ([`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)): `npm test` и проверка запуска веб-чата, затем сервер по SSH получает команду выложить этот коммит. Сервер сам забирает его из GitHub, собирает образ из `Dockerfile`, перезапускает бота и ждёт в логе «Бот @… запущен»; если бот не поднялся — откатывается на предыдущую рабочую версию. Ручной запуск — Actions → Test and Deploy → Run workflow.

Секреты репозитория: `DEPLOY_SSH_KEY` (ключ, которому на сервере разрешена только выкладка), `DEPLOY_KNOWN_HOSTS` (ключ хоста), `DEPLOY_TARGET` (`пользователь@хост`).

## Панель мастера

Команды: `/panel`, `/chats`, `/bookings`, `/settings`, `/help`. У владельца ещё `/venues` и `/new` — см. [«Несколько заведений»](#несколько-заведений).

- **Ждут ответа** — переписки, где бот позвал мастера.
- **Мои** — переписки, которые мастер сейчас ведёт сам.
- **Текущие** — все переписки за последние сутки, в том числе завершённые.
- **Незавершённые** — клиент писал за последнюю неделю, но так и не записался.
- В карточке переписки: «Перехватить» / «Взять диалог» (бот замолкает, сообщения мастера уходят клиенту), «Вернуть боту», «Отправить черновик», «Бот, попробуй ещё», «Завершить диалог». Перехватить можно снова в любой момент.
- «Вернуть боту» и «Бот, попробуй ещё»: бот перечитывает переписку с того места, где позвал мастера или где мастер взял диалог, и отвечает на сообщения клиента, на которые никто не ответил по существу. Если ответа ждать нечему, клиенту ничего не уходит.
- Если вопрос ждал мастера, а на новые вопросы клиента бот за это время ответил сам, карточка и черновик остаются. Когда карточек по клиенту несколько, «Отправить черновик» работает только в последней — в ней все вопросы и весь черновик. Если черновик был только на новый вопрос, после отправки прежний снова ждёт мастера.
- В просмотре переписки реакции клиента показаны как «👍 на сообщение бота «…»», а у фото, голосовых и файлов есть кнопки — по ним бот присылает вложение ещё раз.
- «Завершить диалог» возвращает переписку боту и убирает её из «Незавершённых»; следующее сообщение клиента начинает новый разговор.
- Ответ реплаем на уведомление уходит этому клиенту — даже если мастер не закончил настройку точки.
- Обычные сообщения идут туда, что мастер выбрал последним: в диалог, который он взял, или в настройку точки, которую открыл. Переключают кнопки «Писать сюда» (в переписке и под новым сообщением клиента) и «Писать в настройку». Если ответ сейчас ушёл бы не этому клиенту, под его новым сообщением так и написано.
- Настройку точки, которую мастер 15 минут не трогал, бот считает отложенной: когда клиент напишет снова или мастер ответит ему реплаем, обычные сообщения опять идут клиенту. Сама настройка не пропадает — к ней возвращает «Писать в настройку».
- Если диалог, который ведёт один мастер, вернул боту или завершил другой, первому приходит сообщение об этом.
- **Записи** и **Свободные окна** — просмотр и отмена записей (клиент получит сообщение).

Если вы проверяете бота один и за клиента, и за мастера, создайте второго бота и укажите его токен в `ADMIN_BOT_TOKEN` — панель переедет туда, а основной бот будет вести себя с вами как с клиентом.

## Как не ставить «прочитано» (Telegram Business)

В обычном чате с ботом Telegram сам отмечает сообщения прочитанными — бот на это повлиять не может.

Чтобы сообщения действительно оставались **непрочитанными**, подключите бота к личному аккаунту мастера через Telegram Business (Premium не нужен):

1. Настройки → Telegram для бизнеса → Чат-боты → выбрать своего бота.
2. Разрешить боту отвечать на сообщения и отмечать их прочитанными.
3. Выбрать, в каких чатах бот работает (например, во всех, кроме контактов).

Тогда бот отвечает клиентам прямо из личного аккаунта мастера и отмечает сообщение прочитанным только когда уверенно ответил. Если бот не знает ответа, он пишет клиенту от имени мастера «уточню и скоро отвечу» и зовёт мастера. Если случился сбой ИИ — бот молчит, и сообщение висит непрочитанным, как будто мастер его ещё не видел. Если мастер ответил клиенту сам — бот в этом чате замолкает, пока его не вернут кнопкой.

## Смена точки и передача мастеру

Всё делается из Telegram, в «Настройки точки»:

- **Импорт с Яндекс.Карт** — пришлите ссылку на организацию (`yandex.ru/maps/…`, `maps.yandex.ru/…`, короткую `yandex.ru/maps/-/…`): бот прочитает карточку и прайс, покажет, что понял, и сохранит после подтверждения. График бот берёт из разметки карточки (`<meta itemprop="openingHours">`): в тексте страницы он свёрнут, и видно только «Открыто до 22:00».
- **«Обратите внимание»** — над данными, которые бот показывает после импорта и правок (и в «Заведение создано», и приглашённому администратору): ❗ — без чего бот не сможет работать (нет графика, нет услуг, Яндекс пишет «больше не работает»), • — что проверить (услуги без цены, нет имён мастеров, перерыв или работа после полуночи — их нет в расписании бота, в чём ИИ сомневался). Без графика бот не называет часы и не записывает, а зовёт мастера — а не отвечает клиентам «у нас выходной».
- Если импорт не получился (капча, ошибка Яндекса, сбой ИИ), мастер видит только просьбу прислать скриншоты карточки и прайса или текст, а владелец бота получает техническую причину: что ответил Яндекс на каждый запрос (HTTP-статус, итоговый адрес после редиректов, капча), что сказал ИИ и чем закончился запасной путь через web_fetch. Те же строки пишутся в лог: `Яндекс.Карты: … → Карточка: HTTP …`, `Яндекс.Карты: график в разметке карточки — …` и `Импорт с Яндекс.Карт не удался: …`.
- **Правки словами** — «стрижка теперь 2000», «по воскресеньям выходной», можно прислать фото прайса.
- **Знания** — любые заметки: парковка, оплата, правила опоздания, акции. Бот отвечает по ним клиентам. Когда мастер возвращает диалог боту, свой ответ клиенту можно одной кнопкой сохранить в знания.
- **Длина слота** (15–60 мин) и демо-занятость.
- **Пригласить мастера** (только владелец) — одноразовая ссылка на 7 дней. Мастер открывает её и становится администратором: если точка уже загружена, он сразу видит её данные, если нет — получает предложение прислать ссылку на свою точку с Яндекс.Карт.
- **Сброс** (только владелец) — вернуть демо-данные, чтобы передать бота другому мастеру.

## Несколько заведений

Один бот обслуживает сколько угодно заведений, и у каждого свои данные, переписки, записи и администраторы. Клиент попадает в заведение по его ссылке `https://t.me/<бот>?start=<ссылка заведения>` и дальше пишет ему; кто открыл бота без ссылки — в основное заведение (сначала это точка, которая была в боте до обновления).

**Новое заведение.** Владелец пишет боту `/new` и ссылку на карточку в Яндекс.Картах (или нажимает «➕ Новое заведение» в `/venues`). Бот загружает карточку и прайс, создаёт заведение и присылает — сверху «Проверьте, прежде чем отдавать ссылку клиентам» (то же, что «Обратите внимание» в настройке точки), а затем:
- ссылку для клиентов — её можно публиковать;
- одноразовую ссылку для администратора (7 дней) — её пересылают представителю заведения. По ней он становится администратором только этого заведения и сразу видит его данные, а уведомления о клиентах заведения дальше получает он, а не владелец (включить их владельцу снова — «Уведомления» в панели заведения).

Нет карточки или Яндекс не пускает — «📝 Создать пустое»: заведение описывают словами или скриншотами, ссылки приходят после сохранения.

**`/venues`** (только владелец) — список заведений. В карточке заведения: его панель, новая ссылка для администратора, администраторы (можно убрать), отдельный бот, «сделать основным», удалить (переписки и записи уезжают в архив `data/venues/_deleted`).

**Роли.** Владелец (`OWNER_IDS` или ссылка `own_…` из лога, одна на все заведения) — владелец всех заведений: создаёт их, назначает администраторов, видит технические причины сбоев. Администратор — панель своего заведения и ничего больше. Все остальные — клиенты. Администратор одного заведения может написать другому как клиент, а команды панели всё равно про его заведение. Если человек администратор нескольких заведений (например, владелец), над уведомлением написано, из какого оно заведения, а ответ реплаем уходит туда, откуда уведомление.

### Отдельный бот у заведения

Пока все заведения в общем боте. Перевести заведение в собственного бота — `/venues` → заведение → «🤖 Отдельный бот»:
- **«Создать бота в Telegram»** (Telegram Managed Bots): Telegram открывает экран создания бота с уже подставленными названием и адресом, и после «Создать» бот сам подключается к заведению — токены копировать не нужно. Кнопка появляется, когда для общего бота в @BotFather включено управление другими ботами (Managed Bots) и бот перезапущен.
- **«Прислать токен»** — бот, созданный в @BotFather (`/newbot`). Сообщение с токеном бот сразу удаляет.
- **Запас** — боты, отключённые от заведений или добавленные командой `pool add`. Бот из запаса получает название и описание заведения.

Переписки, записи и администраторы при переезде остаются. Клиентам, которые напишут в общий бот, он подскажет новый адрес, администраторам — где теперь панель. «Вернуть в общий бот» — свой бот уходит в запас.

### Через Claude

Ссылку на карточку можно отдать Claude (порядок — в [CLAUDE.md](CLAUDE.md)): он прочитает карточку, положит данные заведения в `venues/<ссылка>.json` и откроет PR. После мержа автодеплой выкладывает бота, бот при запуске создаёт заведение и присылает владельцу в Telegram ссылку для клиентов и ссылку для администратора. Формат файла — [venues/README.md](venues/README.md).

### Управление с сервера

Запущенным ботом можно управлять из консоли сервера — так это делает и Claude, если у него есть доступ к серверу:

```bash
docker exec <контейнер> node bot/cli.js help
docker exec <контейнер> node bot/cli.js add https://yandex.ru/maps/org/…    # заведение по карточке → ссылки
docker exec <контейнер> node bot/cli.js list
docker exec <контейнер> node bot/cli.js invite borodach                      # новая ссылка для администратора
docker exec <контейнер> node bot/cli.js admin borodach 123456789 Руслан      # администратор по Telegram ID
docker exec <контейнер> node bot/cli.js newbot borodach                      # ссылка «создать бота» (Managed Bots)
echo "$TOKEN" | docker exec -i <контейнер> node bot/cli.js bot borodach -    # свой бот по токену
```

Команды идут боту через сокет `data/control.sock`, открытый только пользователю, от которого запущен бот. `--json` — ответ для скриптов.

### Где данные

`data/state.json` — первое заведение (на старом месте: откат на прежнюю версию найдёт свои данные), `data/venues/<id>/state.json` — остальные, `data/platform.json` — список заведений, ссылки и отдельные боты с их токенами, поэтому папку `data/` никому не отдавайте.

## Настройки

Основные переменные — в `.env.example`. Тонкая настройка: модель (`ANTHROPIC_MODEL`, по умолчанию `claude-opus-5-5`), вдумчивость ответа (`ANTHROPIC_EFFORT`, по умолчанию `high`; `low` — быстрее и дешевле), таймаут ИИ (`LLM_TIMEOUT_MS`), порог уверенности (`CONFIDENCE_THRESHOLD`), скорость «печатает…» (`TYPING_*`).

## Структура бота

```
bot/index.js      — запуск, polling, напоминания
bot/platform.js   — несколько заведений: какому заведению апдейт, ссылки, роли, отдельные боты
bot/venues-ui.js  — экраны владельца: /venues, /new
bot/control.js    — управление с сервера (сокет), bot/cli.js — команды к нему
bot/app.js        — одно заведение — клиенты: диалог, «печатает…», передача мастеру, Business
bot/console.js    — панель мастера: переписки, записи, настройки, приглашения
bot/assistant.js  — промпт, инструменты (слоты, запись, отмена), ответ ИИ
bot/schedule.js   — слоты и записи
bot/shop.js       — данные точки (демо, нормализация)
bot/setup.js      — импорт точки с Яндекс.Карт и правки словами/фото
bot/review.js     — что бот просит проверить в данных точки («Обратите внимание»)
bot/yandex.js     — загрузка карточки организации, график из её разметки
venues/           — заведения, подготовленные заранее (создаются при запуске)
test/             — тесты: npm test
```
